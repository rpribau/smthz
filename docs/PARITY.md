# Desktop parity ledger

Source root: `reference/orca-1.4.238`. Rebuilt 2026-10-31 from `docs/PARITY-AUDIT.md` (code/doc inventory, not a runtime audit) plus the wave 10 deliveries recorded in AGENTS.md. `docs/PARITY-AUDIT.md` holds the per-feature rows, sizes and work packages; this ledger is the per-area summary. Update a row only with evidence (file, test, or a recorded coordinator run).

Status vocabulary (same as the audit): **Real** = code reaches a real backend and a run is recorded; **Partial** = some real behaviour, named gaps; **Visual-only** = UI exists, backend stubbed or disabled (`VISUAL-ONLY`); **Missing** = no code; **Deferred** = out of agreed scope. Allowed final outcomes stay: proved, approved native equivalent, explicitly approved reduction, or deferred by agreed scope. A mock or disabled control does not establish parity.

Overall estimate (audit §3, judgment, not measurement): **≈ 8% functional, ≈ 20% visual**, before wave 10. Wave 10 moved terminal transport, tab groups and keybindings forward; no re-estimate yet.
